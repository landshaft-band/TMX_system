# Project Context

## Назначение

Wagon WMS/MES — desktop-система на Python + PyQt6 для склада производства железнодорожных вагонов. Проект работает на демонстрационном backend: данные лежат в `data/mock_data.py`, интеграции и устройства имитируются сервисами. Архитектура подготовлена к подключению реальной БД, 1С, сканера штрих-кодов и умных весов.

## Архитектура

- `main.py` — запуск приложения, иконка окна, `QApplication`.
- `ui/` — главное окно, стили, общие компоненты.
- `ui/pages/` — страницы интерфейса.
- `services/` — бизнес-логика и интеграционные заглушки.
- `data/` — демонстрационные данные.
- `models/` — enum/dataclass-заготовки.
- `reports/` — PDF-отчёты при запуске из исходников.
- `docs/` — инженерная документация.

## Основные страницы

- `Главное` — KPI, журнал событий, зоны склада, аналитика.
- `Приёмка` — сканирование, весы, контроль расхождений, PDF по приёмке.
- `Отгрузка` — партии, жизненный цикл, история партии, PDF, выгрузка в 1С.
- `Заказы` — реестр и создание заказа, статусы заказа.
- `Логистика` — приоритеты, транспорт, расчёт транспорта.
- `Интеграции` — 1С, очередь обмена, аудит, цифровой паспорт партии, номенклатура, допуски.
- `Пользователи` — таблица пользователей.
- `Отчёты` — генерация PDF и выбор папки отчётов.

## Сервисы

- `barcode_service` — генерация штрих-кодов.
- `scale_service` — состояние и симуляция весов.
- `discrepancy_service` — расчёт отклонения веса.
- `notification_service` — уведомления руководителю.
- `onec_service` — демонстрационный обмен с 1С.
- `pdf_report_service` — генерация PDF через ReportLab.
- `event_log_service` — централизованный журнал событий.
- `analytics_service` — расчёт KPI dashboard.
- `audit_service` — журнал аудита действий пользователей.
- `auth_service` — роли и права действий.
- `settings_service` — пользовательские настройки, включая папку отчётов.

## Бизнес-процессы

1. Приёмщик сканирует упаковку.
2. Система получает или симулирует вес.
3. Вес сравнивается с плановым.
4. Нормальная упаковка принимается.
5. Расхождение попадает в проблемные позиции и уведомления.
6. Менеджер создаёт заказ и формирует партию.
7. Логист рассчитывает транспорт.
8. Партия проходит статусы и отгружается.
9. По партии формируется PDF.
10. Закрытая отгрузка выгружается в 1С.
11. Действия пишутся в event log и audit log.

## Роли и вкладки

- `Администратор`: все вкладки.
- `Менеджер`: Главное, Отгрузка, Заказы, Интеграции, Отчёты.
- `Кладовщик`: Главное, Приёмка.
- `Приёмщик`: Главное, Приёмка.
- `Логист`: Главное, Логистика, Отгрузка, Интеграции.
- `Руководитель`: Главное, Заказы, Отгрузка, Логистика, Интеграции, Пользователи, Отчёты.

Видимость вкладок задаётся в `ROLE_VISIBLE_PAGES` внутри `ui/main_window.py`. Права действий задаются в `services/auth_service.py`.

## Правила проекта

- Не переписывать проект с нуля.
- Не ломать layout и расположение блоков.
- Не дублировать сервисы: сначала искать существующий сервис.
- Использовать `ui/styles.py` и `ui/components.py` для общего UI.
- Все новые действия писать в `event_log_service`.
- Важные пользовательские действия писать также в `audit_service`.
- Новые функции делать модульно, через `services/`.
- Перед изменениями читать `PROJECT_CONTEXT.md`.

## UI/UX правила

- Industrial enterprise UI: SAP/MES/WMS/SCADA style.
- Тёмный sidebar.
- Строгие таблицы как основной элемент интерфейса.
- Минимальный `border-radius`.
- Минимальные тени и glow-эффекты.
- Muted colors, без яркого web-style.
- Плотные отступы и компактная типографика.

## Как работать с проектом

1. Сначала изучить структуру и текущую страницу.
2. Проверить, есть ли подходящий компонент или сервис.
3. Вносить минимальные изменения.
4. Не пересоздавать страницы без необходимости.
5. Не менять роли и навигацию без явной задачи.
6. После изменений запускать:

```powershell
.\.venv\Scripts\python.exe -m compileall main.py ui data services models
```
