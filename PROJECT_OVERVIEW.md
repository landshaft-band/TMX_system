# Wagon WMS/MES MVP

Desktop-приложение на Python + PyQt6 для демонстрации WMS/MES-системы склада комплектующих производства железнодорожных вагонов.

Проект является MVP для диплома: реальной базы данных, API, авторизации, 1С, сканера и весов пока нет. Демонстрационные данные хранятся в памяти и в `data/mock_data.py`.

## Быстрый запуск

```powershell
cd C:\Users\winda\Documents\diplom
.\.venv\Scripts\activate
python main.py
```

Или без активации окружения:

```powershell
.\.venv\Scripts\python.exe main.py
```

## Что реализовано

### Интерфейс

- PyQt6 desktop-приложение.
- Светлая промышленная тема в стиле WMS/MES/SCADA.
- Тёмный sidebar.
- Верхняя панель с логотипом `tmh.png`, заголовком, выбором роли и краткой статистикой.
- Навигация через `QStackedWidget`.
- Основные страницы:
  - `Главное`;
  - `Приемка`;
  - `Отгрузка`;
  - `Заказы`;
  - `Логистика`;
  - `Отчёты`;
  - `Пользователи`.

### Предметная область

Демонстрационные данные адаптированы под производство железнодорожных вагонов:

- вагонные окна;
- вагонные двери;
- листы металла;
- металлические профили;
- болты М8, М10, М12, М16;
- гайки;
- шайбы;
- заклёпки;
- уплотнители;
- крепёжные комплекты;
- элементы кузова вагона.

Все исходные демонстрационные данные находятся в:

```text
data/mock_data.py
```

## Роли и права

Роли переключаются в верхней панели.

Реальной авторизации нет. Ограничения реализованы через `services/auth_service.py`.

Роли:

- `Приёмщик`;
- `Менеджер`;
- `Логист`;
- `Руководитель`;
- `Администратор`.

Если прав не хватает:

- часть кнопок disabled;
- часть действий показывает `QMessageBox.warning`.

Администратор имеет полный доступ.

## Приёмка

Файл страницы:

```text
ui/pages/receiving_page.py
```

Реализовано:

- выбор поставки;
- паспорт партии;
- таблица состава партии;
- сканирование штрих-кода;
- генерация штрих-кода вида `BC-2026-000001`;
- демонстрационное подключение умных весов;
- симуляция веса рядом с плановым;
- проверка допустимого отклонения;
- таблица принятых упаковок;
- таблица проблемных позиций;
- PDF акт расхождения;
- PDF паспорт партии.

Сценарий проверки:

1. Открыть приложение.
2. Выбрать роль `Администратор` или `Приёмщик`.
3. Открыть `Приемка`.
4. Нажать `Сгенерировать штрих-код`.
5. Нажать `Сканировать`.
6. Нажать `Подключить весы`.
7. Нажать `Симулировать вес`.
8. Нажать `Проверить и принять`.

Если отклонение в норме, упаковка попадёт в `Принятые упаковки`.
Если отклонение выше допуска, упаковка попадёт в `Проблемные позиции`, появится warning и демонстрационное уведомление руководителю.

## Отгрузка

Файл страницы:

```text
ui/pages/shipping_page.py
```

Реализовано:

- таблица партий для отгрузки;
- колонка `Статус 1С`;
- детали выбранной партии;
- progress bar готовности;
- список заказов к отгрузке;
- жизненный цикл отгрузки;
- история партии;
- карточка интеграции с 1С;
- формирование партии;
- печать этикеток;
- отгрузка;
- перевод в следующий статус;
- PDF отчёт по отгрузке;
- выгрузка закрытых отгрузок в 1С.

Статусы отгрузки:

- `Черновик`;
- `Формируется`;
- `Готова к отгрузке`;
- `Отгружена`;
- `Закрыта`;
- `Выгружена в 1С`.

Статусы 1С:

- `Не выгружено`;
- `Готово к выгрузке`;
- `Выгружено в 1С`;
- `Ошибка синхронизации`.

Сценарий проверки 1С:

1. Выбрать роль `Администратор` или `Менеджер`.
2. Открыть `Отгрузка`.
3. Выбрать партию.
4. Кнопкой `Перевести в следующий статус` довести её до `Закрыта`.
5. Нажать `Выгрузить закрытые отгрузки в 1С`.

Результат:

- успешная выгрузка меняет статус на `Выгружено в 1С`;
- демонстрационная ошибка меняет статус на `Ошибка синхронизации`;
- событие попадает в журнал.

## Где подключать реальные системы

### Backend

Лучшее место для подключения backend — слой `services/`.

Постепенно нужно заменить прямое чтение и изменение `data/mock_data.py` на:

- HTTP API;
- локальную БД;
- репозитории;
- DTO/dataclass-модели.

### 1С

Подключать в:

```text
services/onec_service.py
```

Возможные варианты:

- HTTP-сервис 1С;
- COMConnector;
- обмен XML/JSON;
- файловый обмен.

### Весы

Подключать в:

```text
services/scale_service.py
```

Возможные варианты:

- COM-порт;
- TCP/IP;
- SDK производителя;
- драйвер весов.

### Сканер

Подключать в:

```text
services/barcode_service.py
ui/pages/receiving_page.py
```

Большинство USB-сканеров работают как клавиатурный ввод, поэтому текущий `QLineEdit` уже подходит для MVP.

## Рекомендации для продолжения

1. Не переписывать UI сразу.
2. Сначала выделить настоящие модели данных.
3. Заменить `mock_data.py` на репозиторий или API-клиент.
4. Добавить сохранение событий и операций в БД.
5. Подключить реальные устройства через сервисы.
6. Интеграцию с 1С делать только через `onec_service.py`.
7. PDF оставить через `PDFReportService`, расширяя шаблоны отчётов.
